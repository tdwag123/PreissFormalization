Performance diagnosis
Large cached imports are the bottleneck, rather than a hard theorem or absent
Orthogonal artifact. During the slow checks compilers spent only 7--18 CPU seconds
across minutes of wall time and remained at roughly 100--150 MB working sets.
The legacy Planes.setup.json includes olean.server and olean.private files for all
transitive imports. Pinned mathlib uses the modern module system. The controlled
modern-module check was substantially faster, though differing cold-cache state
means the exact speedup should not be treated as a benchmark. Use the modern convention only in branches whose transitive dependencies permit it;
see the interoperability correction below.
Do not remove module artifacts or disable security tools to improve build speed.
An unrelated user Lean 4.24 build was observed and left untouched.

Additional import organization findings
Use @[expose] public section for definitions that need downstream unfolding;
that is the actual convention in the pinned mathlib Hausdorff, Support,
CompactlySupported, and Orthogonal modules. The timed scratch did not test
cross-file unfolding. Keep the definition modules' imports smaller:
- Gaussian moment definitions need exp and integration, not GaussianIntegral.
- Flatness definitions need planes, infDist, integrals, and compact support;
  they do not mathematically depend on Gaussian moments or Marstrand's theorem.
- Weak linear approximation needs planes, infDist, Hausdorff measure; it does
  not mathematically depend on the tangent-measure implementation.
These current transitive dependencies should be removed in the new organization.

Recommended public API in namespace Preiss:
- LipschitzPiece (m : Nat) (X : Type*) [MetricSpace X], a structure with
  domain : Set (Euclidean m), toFun : domain -> X, and
  lipschitz : exists K : NNReal, LipschitzWith K toFun.
- Dependent CoeFun instance permits writing p x for x : p.domain.
- LipschitzPiece.range p := Set.range p.toFun.
- CountablyCoveredByLipschitzPieces m s: a countable set of pieces covers s
  pointwise, without a null remainder. The family may be empty.
- CountablyLipschitzCovered m s retains the previous full-domain-map convenience
  predicate. Equivalence with partial-domain coverage needs an extension theorem
  specific to the target, so it must not be assumed for an arbitrary metric target.
- CountablyRectifiable m s: exists t with partial-domain countable coverage and
  HausdorffMeasure m (s minus t) = 0.
- IsRectifiableMeasure m mu: mu absolutely continuous with respect to Hm, and
  exists a CountablyRectifiable carrier s with mu(s complement)=0.
- Plane and IsLipschitzGraph retain the previously proposed Euclidean definitions.

The Lipschitz bound is an existential proof field rather than arbitrary numeric
structure data; different witnesses for the same domain and map do not distinguish
pieces. Measurability is not imposed on parametrization domains or graph maps.
The rectifiability predicates use the existing Borel-space Hausdorff measure API.
Measurable carriers, sigma-finiteness, finite-mass pieces, and extension to full
maps remain separate lemmas. The full proposal uses only four modern mathlib
imports (PiL2, Lp.MeasurableSpace, Measure.Hausdorff, and Orthogonal), and
@[expose] public section. No permanent source file was changed.

Performance caution
The223s canonical check, despite modern headers and a previously warm import
set, shows the earlier24s timing is not a reliable performance guarantee. Shared
